Catalogs

Storage and message semantics are explicit.

Give the catalog a reliable core

Ferrocat handles Gettext PO, ICU MessageFormat v1 and FCL catalogs. Keep source text, contexts, translations, origins, plural forms and obsolete entries in a model the application can inspect. FCL uses one canonical entry per line for Git review and automation. PO remains useful where translator tools read the file directly. Format conversion is a distinct operation with explicit source and target modes.

Collaboration

Automation has a visible boundary.

Keep edits authoritative

Merge updates without fuzzy guessing or hidden identity changes. A three-way merge preserves deletions and reports modify/delete conflicts instead of silently choosing a winner. Machine-managed value metadata can detect later hand edits. High-level writers clear machine metadata when a person edits the value. Human corrections remain reviewable catalog data.

Release checks

Structure matters as much as wording.

Check the message before it ships

Analyze placeholders, formatters, plural/select branches and rich-text tags. Audit missing locales, empty or stale translations, obsolete entries and metadata conflicts. Coverage and review reports support translator handoffs and release gates. ICU scope is MessageFormat v1. Host frameworks own extraction, runtime adapters and UI integration; Ferrocat supplies the catalog semantics underneath them.
