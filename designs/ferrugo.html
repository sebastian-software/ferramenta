Native rendering

A small explicit path.

Keep the runtime focused

The CLI, Rust library and Node.js package use the native backend. PDFium is not a runtime dependency and is not bundled. External renderers serve maintainer comparisons rather than silently becoming a runtime fallback. The practical scope is server-side previews, document intake, thumbnails and automation workflows.

Resource policy

Make the budget part of the job.

Put limits around the document

Choose explicit memory and timeout budgets for bounded rendering. Use typed diagnostics and unsupported-feature boundaries when a document exceeds the engine's current scope. Keep the file and resource policy close to the caller instead of presenting every PDF as a safe, inexpensive input.

Evidence

A useful preview subset, openly tested.

Be precise about fidelity

Generated and curated corpora, golden images and comparison oracles expose the documents the renderer handles and the gaps that remain. The project does not claim pixel-perfect parity across the full PDF format. PDF editing, signing, dynamic XFA and a complete interactive viewer are outside the current product path. WASM is a secondary compatibility profile; the main runtime is Rust-native on the server or local machine.
