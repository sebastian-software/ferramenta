# Imagegen prompt set

Mode: built-in Imagegen. Six complete homepage design concepts, with one targeted hero correction. All selected images and their provenance sidecars are saved in this directory.

The source copy in `content/` remains the authority for text, API behavior and recorded measurements. These are raster design studies.

## 29 · Ferromark · Editorial folio

[View concept](a-ferromark.html) · [PNG](29-editorial-folio-ferromark.png) · [Provenance](29-editorial-folio-ferromark.png.json)

```text
Use case: ui-mockup. Asset type: a high-fidelity full-page desktop homepage design exploration, one complete page per image. This is a fresh art-directed visual concept for the Ferramenta family of Rust libraries. The request is a holistic design direction, including the tables, content hierarchy, typography and overall composition.

Preserve the approved brand idea: warm, light, refined precision engineering, satin steel and a restrained oxide accent. The reference instrument must have a meaningful relationship to the library. Use ONE substantial object illustration in the hero only, never a wall of product photos below it. Preserve useful editorial content and technical evidence. Keep everything light-theme-only with a clean warm-white reading ground (#FCFCFA or white), graphite text (#2D3632), readable secondary ink (#5C665E), and a measured oxide accent (#8C4D30).

Critical current request: all decorative section backgrounds have been rejected. NO material background strips, gradients in section grounds, grain on the page, wave edges, diagonal section shapes, foggy fade-outs or dark sections. Materials belong in the actual hero object and small supplied product symbol only. Create variety through the composition, type, hierarchy, reading measures, examples, charts and table design, not by adding background treatments. No decorative horizontal separators between stories. Tables may have functional rules, but must be intentionally designed rather than copied from a generic UI kit.

The whole page must breathe: wide column gutters, approximately 120–160px desktop separation between major stories, readable body leading around 1.6–1.75, and clear space around table captions, notes and next actions. This is a complete homepage with interesting lower content, not a huge hero plus a sparse feature grid. Avoid both giant blank wastelands and compressed tiny copy. Use around 5 considered content moments plus a modest footer. No fake testimonials, invented usage statistics or unsupported API claims.

Output ONE full-page desktop website comp approximately 1200px wide by 2800–3400px tall, head-on and uncropped, no browser frame, presentation board, side-by-side variants or annotations outside the web page. All visible website text in US English. Follow the product copy and exact numeric data supplied below; the text files remain the accuracy authority. The object reference has alpha: do not bring a black backdrop from the image viewer into the design.

Direction: Editorial folio
Build the page like a carefully art-directed technical magazine, with ONE large mechanical hero at the upper right and an expressive but light regular-width grotesk product title on the left. After the hero, deliberately vary the composition: an opening feature taking about seven columns plus a narrow, lower-starting factual side note; a full-width measured figure; then a broad text story with a compact open policy ledger as its companion. Use different spans and vertical alignments; do not repeat rows of two equal columns.
Table design is editorial: left-aligned natural-language labels, numeric columns aligned on decimals, real units in headings, very generous row leading, a small caption and a plain provenance note below. No enclosing box, header fill, zebra stripes or vertical gridlines. Use only a few short functional column rules if needed. The Ferromark policy comparison should read like a publication's two clear policy cases. The Ferroni feature comparison should read like a quiet index of capabilities; its benchmark table is a separate measured figure. Prose and figure captions must have distinct hierarchy. The closing install action is part of the final story, not a big empty CTA band. One regular humanist grotesk family for navigation, article text, headlines and data; real monospaced code only. This should feel like a coherent premium journal about precision tools, with richer content and confident empty space.

Reference roles: Image 1 is the Ferromark document registration instrument, for the exact meaningful hero object and material identity. Image 2 is the existing Ferromark symbol, used small with a real text wordmark. Neither reference is an existing page layout. Create the complete new composition described above.

Product content:
Header: Ferromark. Overview. Start with Rust. Rendering. Benchmarks. GitHub. The Ferramenta family.
Hero title: Ferromark.
Purpose headline: Markdown, ready for your pipeline.
Hero description: Turn Markdown into HTML and the metadata around it. A focused Rust engine for the documents that get complicated.
Primary action: Start with Rust. Secondary action: Node.js guide.

Working example title: See what a document becomes.
Markdown input is the heading "# Release notes", followed by the list "- Clear structure" and "- Useful metadata". The rendered output must show the heading Release notes and exactly those two list items.

Opening story: Correctness is a contract.
A Markdown engine has to earn trust on the awkward document: a nested list, a reference that moves, a table with real content, or a footnote added at the last minute. Ferromark starts with CommonMark and GFM, then makes the publishing features explicit.
Specification profiles turn off publishing extras so that conformance can be checked on its own terms. Optional heading IDs, front matter and footnotes belong to a documented output contract.
A small publishing ledger: Front matter — extracted as raw text; Heading IDs — configurable output; Footnotes — document references and notes; Rendering hooks — your application decides.

Measured figure title: Speed, with the conditions attached.
Fresh throughput relative to Ferromark v2, higher is faster.
Exact rows: Ferromark v2 1.00×; Ferromark v1 0.48×; pulldown-cmark 0.38×; md4c 0.29×; Bun native 0.17×.
Provenance: September 21, 2026. Apple M1 Pro. Revision 39b1f0b7. 50 documents with equivalent HTML across five engines, from a frozen 57-document corpus. Other cases remain diagnostics. Fresh and reuse are separate lifecycles. These recorded figures do not promise every workload.
Link: Read the measurements and exact flags.

Policy reference title: Recognition is not permission.
The engine can recognize raw HTML without granting permission to emit it.
Table columns: API | Default | For untrusted Markdown.
Exact rows: Rust | Raw HTML passthrough | Enable sanitize.
Node.js | Escaped HTML and filtered URL schemes | Keep renderPolicy: 'untrusted'.
Footnote: Custom hooks and highlighter HTML are written verbatim. They must escape untrusted values themselves.
Link: Choose your rendering policy.

Publishing note: The document, beyond paragraphs.
Extract front matter as raw text; the application interprets YAML or TOML. Configure heading IDs and footnotes. Keep templates, translation, routing and syntax highlighting outside the renderer.
Closing: Build the pipeline that fits.
Start with the Rust crate, or use the native engine through Node.js. Pair Ferromark with Ferriki for syntax highlighting; neither engine requires the other.
Install: cargo add ferromark.
Footer: Ferromark. Part of Ferramenta. GitHub. Imprint. Privacy.
```
