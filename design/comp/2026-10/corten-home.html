Ferramenta: Seven Rust engines for the jobs every toolchain has.

Regular expressions, syntax highlighting, Markdown, spell checking, translation catalogs, file discovery, PDF previews. Each engine follows the standard its field already agreed on, and each works on its own.

See the seven engines GitHub

Seven engines, each for one job

Every engine works on its own. Where two fit together, the entry says so.

  • Ferroni

    Regular expressions

    stable

    Runs the regular expressions that TextMate grammars are written in, with the scanner editors and highlighters drive built in.

    Oniguruma carried this job for more than twenty years, and its C project ended in April 2025. Ferroni continues the engine in memory-safe Rust.

    For anyone who tokenizes code the way an editor does.

    Succeeds
    Oniguruma / vscode-oniguruma
    Checked against
    Oniguruma compatibility oracle
    Fits
    • Ferriki runs on it
    Release
    v1.4.2

    ferroni.dev

  • Ferriki

    Syntax highlighting

    alpha

    Highlights code with the grammars and themes your editor uses.

    Shiki brought editor-grade highlighting to the web. Ferriki keeps its contract and moves the engine from JavaScript and WASM to native Rust.

    For docs sites, blogs, and build tools that render code.

    Succeeds
    Shiki
    Checked against
    Mirrored Shiki test suite
    Fits
    • Runs on Ferroni
    • Pairs with Ferromark
    Release
    v0.3.0

    ferriki.dev

  • Ferromark

    Markdown to HTML

    stable

    Turns Markdown into HTML, sanitized by default, and is among the fastest engines for the job.

    CommonMark settled what Markdown means. Ferromark carries that contract, plus GFM, into a renderer built for speed.

    For static sites, docs pipelines, and any app that renders what people write.

    Built to
    CommonMark / GFM
    Checked against
    CommonMark & GFM conformance
    Fits
    • Pairs with Ferriki
    • Palamedes runs on it
    Release
    v2.1.1

    ferromark.dev

  • Ferrolex

    Spell checking

    alpha

    Checks spelling in prose and in code, and gives the same suggestions every time.

    Hunspell set the dictionary standard. Ferrolex reads those dictionaries and adds compiled dictionaries and code-aware checking.

    For editors, linters, and CI checks.

    Succeeds
    Hunspell
    Checked against
    Hunspell oracle · deterministic suggestion scoring
    Release
    v0.4.0

    GitHub repository

  • Ferrocat

    Translation catalogs

    stable

    Reads, merges, and compiles translation catalogs.

    gettext taught software to speak in catalogs. Ferrocat carries that model into Git and AI workflows, where merges stay conflict-free.

    For teams whose translations live in the repository.

    Built to
    PO / ICU MessageFormat
    Checked against
    Upstream-derived conformance cases · ahead of GNU msgmerge and common PO libraries
    Fits
    • Palamedes runs on it
    Release
    v3.4.2

    ferrocat.dev

  • Ferralk

    File discovery

    stable

    Matches glob patterns and walks file trees in parallel, ahead of globset and fast-glob.

    Every build tool pays for finding files before it does any work. Ferralk keeps zlob's byte-first approach in pure Rust.

    For build tools, linters, and anything that starts with a file list.

    Built to
    Glob syntax / .gitignore rules
    Checked against
    Frozen zlob reference · ahead of globset and fast-glob
    Fits
    • Palamedes runs on it
    Release
    v1.0.0

    GitHub repository

  • Ferrugo

    PDF previews

    early

    Renders previews of PDF files you have no reason to trust.

    PDF previews have meant embedding a browser-sized engine. Ferrugo renders under explicit limits on memory and time, without PDFium.

    For upload pipelines and document viewers.

    Built to
    PDF (ISO 32000)
    Checked against
    Bounded memory and time · no PDFium
    Release
    v0.5.0

    GitHub repository

What earns the rating

  • Proven, not promised

    Where an engine succeeds an established implementation, differential suites measure it against that reference. Claims stay tied to current evidence.

  • Open standards first

    CommonMark, PO files, ICU MessageFormat, Hunspell dictionaries, TextMate grammars. We build on what the ecosystem already agreed on.

  • Match before outrun

    Compatibility comes first. Performance claims follow published benchmarks, never a compatibility asterisk.

stable
Ready to adopt; its interface is settled.
beta
Complete for its scope; details may still change.
alpha
Usable to try; expect gaps and breaking changes.
early
Taking shape; not yet something to depend on.
